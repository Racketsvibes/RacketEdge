## 01. Human Writing Rules — No AI Fingerprints Allowed

### A. The First-Person Affiliate Voice Standard

Chris Davies writes as a real person who plays, tests, and loves racket sports. Every article must sound like Chris is talking directly to the reader over coffee — honest, opinionated, and specific. This is non-negotiable.

> **TONE:** First-person, conversational, enthusiastic but measured. Never corporate, never clinical, never robotic.

| Element | Standard |
|---|---|
| **Voice** | Always write as Chris: *"I've played with this racket for three months..."* / *"In my experience..."* / *"I wouldn't recommend this if..."* |
| **Perspective** | Buyer-first. Help the reader make the right decision, even if that means steering them away from an option. |
| **Register** | Natural, casual-professional. Think magazine columnist, not Wikipedia editor. |
| **Honesty** | Include genuine negatives. Overly promotional content kills trust and Google flags it. |
| **Pacing** | Mix short punchy sentences with longer explanation. Never write 5 sentences of the same length back-to-back. |

### C. Mandatory Human Writing Signals

Every article must include **AT LEAST FOUR** of the following to pass the human-writing test:

- A first-person anecdote or specific personal observation (*"When I tested the Wilson Pro Staff..."*)
- A genuine negative or drawback called out honestly (*"The grip wore down faster than I expected"*)
- A specific comparison rooted in experience (*"This plays closer to the Babolat than the Head"*)
- A direct reader address (*"If you're playing at club level, this is probably overkill"*)
- An unexpected or counterintuitive observation (*"Weirdly, the lighter frame actually gave more power on groundstrokes"*)
- A concrete number or measurement from personal testing (*"After 12 sessions, I noticed..."*)
- Regional/context-specific advice (*"In humid climates, this string loses tension faster"*)
- A hedge based on player type (*"Beginners will love this. Advanced players might find it too forgiving"*)

### D. Sentence Structure & Readability Rules

Google's NLP and AI detectors flag "burstiness" failure — content where every sentence is roughly the same length and structure. Human writing varies dramatically.

> **RULE:** No three consecutive sentences should start with the same grammatical structure. No paragraph of more than 4 sentences should have uniform length.

| Rule | Requirement |
|---|---|
| **Sentence length variation** | Mix very short sentences (4–8 words) with medium (15–25) and occasionally long (30–45). Never write 5 sentences in a row at the same length. |
| **Paragraph length** | 2–4 sentences max for body paragraphs in blog posts. Use single-sentence paragraphs for emphasis. |
| **Sentence starters** | Rotate: Subject-first, prepositional opener, clause opener, conjunction opener ("And", "But", "So" — acceptable in blogging). |
| **Contractions** | Use them freely: don't, it's, you'll, I've, they're. Formal = no contractions. Human blog = always use them. |
| **Rhetorical questions** | Use 1–2 per 1,000 words to break pacing and engage reader. |
| **Dashes and em-dashes** | Use naturally — they're a human writer's punctuation. AI avoids them. |
| **Parenthetical asides** | Use sparingly (1–2 per article) to add a casual, human interjection. |

## 03. Internal Linking Standards

### A. Internal Link Requirements per Post

| Element | Standard |
|---|---|
| **Minimum links** | Every post must contain at least 3 internal links to other pages on racketedge.com. |
| **Maximum links** | Do not exceed 8–10 internal links per 1,000 words. Over-linking dilutes anchor value. |
| **Direction** | Link to pillar pages, category pages, and related product reviews. Avoid only linking to the homepage. |
| **Anchor text** | Use descriptive, keyword-rich anchor text. Never use "click here", "read more", or "this article". |

| **Link opening** | Internal links must open in the **SAME** tab/window. Only external links open in new tabs. |

---

### B. Pillar Page / Hub Structure

racketedge.com must follow a hub-and-spoke architecture for topical authority:

- Pillar pages cover broad topics (e.g., *"Tennis Rackets: The Complete Guide"*) with 2,500–4,000 words
- Spoke pages are specific reviews, comparisons, or guides that link back to the pillar
- Every spoke must link to its parent pillar once, using a relevant anchor
- The pillar must link out to all spoke pages it covers
- Mark pillar posts as **"Pillar Content"** in RankMath (the checkbox in the plugin settings)

---

### C. Anchor Text Rules

| Anchor Type | Standard |
|---|---|
| **Exact match anchors** | Use sparingly — max 20% of internal links. Overuse triggers over-optimization signals. |
| **Partial match anchors** | Target 40–50% of links. Example: "control-focused racket" instead of "best control racket". |
| **Branded anchors** | 10–20% can reference racketedge content ("our full Wilson review"). |
| **Natural anchors** | 15–20% can be natural context anchors ("this comparison", "the racket we tested"). |
| **Never use** | "Click here", "here", "link", "read more", "this post" as anchor text — zero SEO value. |
| **Uniqueness** | The same anchor text must not point to two different URLs. One anchor = one destination. |

## 05. Structured Data & Schema Markup Standards

> **WHY IT MATTERS:** Pages with correct schema earn 20–30% higher CTR. Schema is also the primary bridge between your content and AI Overviews, ChatGPT citations, and Perplexity responses.

### A. Required Schema Types for racketedge.com

| Schema Type | Requirement + Notes |
|---|---|
| **Article / BlogPosting** | Required on EVERY post. Must include: headline, author (Chris Davies), publisher (RacketEdge), datePublished, dateModified, image, description. |
| **Product (Snippet type)** | Required on all review posts and roundup posts. Include: name, brand, description, aggregateRating, review, image. Use Product Snippet type (not Merchant Listing) — this is an affiliate site with no direct purchase. |
| **FAQPage** | Required on all posts that include a FAQ section. Each Q&A pair maps to a FAQPage entity. Critical for AEO/AI Overviews. |
| **BreadcrumbList** | Site-wide. Shows navigation path in SERP. RankMath generates this automatically — confirm it's active. |
| **Organization** | Site-wide in the footer/head. Name: RacketEdge, URL, logo, sameAs (social profiles). Builds Knowledge Panel eligibility. |
| **Person (Author)** | Author entity: Chris Davies. Must include: name, url (author archive), image, description, sameAs (social profiles). Builds E-E-A-T. |
| **ItemList** | Use for roundup posts ("Best Tennis Rackets") to list all products as a structured ItemList. |
| **HowTo** | Use on any "how to" guides (stringing, grip replacement, choosing a racket). Maps to voice search results. |

---

### B. Schema Implementation Rules

| Rule | Standard |
|---|---|
| **Format** | Always use JSON-LD. Never use Microdata or RDFa. JSON-LD keeps markup separate from HTML. |
| **Placement** | In the `<head>` section or just before `</body>`. RankMath places it automatically via its Schema module. |
| **@graph structure** | Connect all schema entities in one `@graph` block so Organization, WebSite, WebPage, Article, Author, BreadcrumbList, and Product reference each other via `@id`. |
| **Only visible content** | Never mark up content that isn't visible on the page. Google penalizes hidden schema. |
| **No self-review** | Do not use Review schema to review your own site. Product review of third-party products (Amazon items) is fine. |
| **Validation** | Validate every post's schema using Google Rich Results Test and Schema.org Validator before publishing. |
| **Conflict prevention** | Disable WooCommerce default schema if installed. RankMath handles all schema — avoid duplicate `@type` blocks. |
| **Date freshness** | Update `dateModified` every time you edit a post. Stale dates hurt Discover and AI citation freshness. |

---

### C. Product Schema — Required Properties (Affiliate Review)

> **FORMAT:** For affiliate review posts, use the Product Snippet type. Do NOT add a price in the `offers` block — you cannot control Amazon's price. Use `aggregateRating` and `review` blocks instead.

Required properties for every product review schema:

```json
{
  "@context": "https://schema.org/",
  "@type": "Product",
  "name": "Wilson Pro Staff 97 v13",
  "brand": { "@type": "Brand", "name": "Wilson" },
  "image": ["https://racketedge.com/images/wilson-pro-staff-97.webp"],
  "description": "2–3 sentence description of the product.",
  "aggregateRating": {
    "@type": "AggregateRating",
    "ratingValue": "4.7",
    "reviewCount": "1",
    "bestRating": "5",
    "worstRating": "1"
  },
  "review": {
    "@type": "Review",
    "author": { "@type": "Person", "name": "Chris Davies" },
    "reviewRating": { "@type": "Rating", "ratingValue": "4.7", "bestRating": "5" },
    "reviewBody": "Honest, experience-based review body text here."
  }
}
```

Also include **pros** and **cons** fields — supported in Google's editorial product schema.

## 06. AEO & GEO — AI Overview, ChatGPT, Perplexity, Claude, Grok, DeepSeek

> **CONTEXT:** AI-referred traffic jumped 527% year-over-year in 2025. 65% of Google searches now end without a click. Getting cited BY AI is the new ranking.

### A. Universal GEO/AEO Content Architecture

| GEO Rule | Requirement |
|---|---|
| **Answer capsule** | Every article must include a 40–60 word direct answer to the main question within the first 150 words. This is the single most important GEO signal. |
| **Fact density** | Include at least one statistic, measurement, or concrete data point every 150–200 words. AI engines prioritize fact-rich content for citation. |
| **Cite authoritative sources** | Cite ITF specs, WTA/ATP standards, academic research, or manufacturer data. AI engines favor content that itself cites credible sources. |
| **Entity naming** | Name the product, technique, or concept explicitly and consistently throughout. Don't use pronouns to replace entity names (helps NLP entity recognition). |
| **Definition-first structure** | Start each major section with a 1–2 sentence canonical definition before expanding. AI uses these as citation anchors. |
| **Comparison tables** | Include at least 1 HTML comparison table per roundup post. AI models extract tabular data more reliably than prose for comparative queries. |
| **Numbered/bulleted processes** | Any "how to" content must use numbered steps. This is the single most cited format in AI-generated responses. |
| **Content freshness** | Update all posts quarterly with a visible "Last Updated" date. Pages not updated quarterly lose AI citations at 3× the normal rate. |

### C. GEO Content Blocks Required in Every Post

## 08. Technical SEO & Core Web Vitals Standards

### A. Core Web Vitals — Google Discover Prerequisite

> ⛔ **CRITICAL:** Passing Core Web Vitals is a prerequisite for Google Discover eligibility. Failing any metric can remove content from the Discover feed entirely.

| Metric | Target + Action |
|---|---|
| **LCP (Largest Contentful Paint)** | Target: under 2.5 seconds. Good: ≤2.5s / Needs Improvement: 2.5–4.0s / Poor: >4.0s. Optimize the hero image — it's almost always the LCP element. |
| **INP (Interaction to Next Paint)** | Target: under 200ms. Replaced FID in 2024. Minimize JavaScript blocking the main thread. |
| **CLS (Cumulative Layout Shift)** | Target: under 0.1. Always specify image width and height in HTML to prevent layout shifts during load. |
| **TTFB (Time to First Byte)** | Target: under 800ms. Use quality hosting (not shared). Consider a CDN. Enable server-side caching. |
| **FCP (First Contentful Paint)** | Target: under 1.8s. Affects perceived performance. Preload the hero image. |

### B. Headline Rules for Discover

| Rule | Standard |
|---|---|
| **Curiosity gap (ethical)** | Write headlines that spark genuine curiosity — not clickbait. Example: *"I Tested 7 Rackets Under $100. One Surprised Me."* is fine. *"You Won't BELIEVE This Racket"* is not. |
